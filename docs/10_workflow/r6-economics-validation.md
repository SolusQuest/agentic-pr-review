# R6 offline economics validation

Run `bash runtime/scripts/verify-r6-economics.sh all` from a clean committed checkout on Linux x64 with the pinned .NET SDK, Python 3, Node 24, installed npm dependencies, clang, zlib development headers and strace. `framework` and `aot` select one actual execution mode; only `all` also proves cross-mode semantic parity. The dedicated `r6-economics-gate` Runtime CI job checks out the exact event-selected commit with read-only permissions and disabled checkout credentials. Existing Runtime and R2–R5 gates remain required.

The fixture executes 82 named cases. `Economics/Verification/GateInventory.cs` separately declares their order and selected input/fault identities; the producer explicitly invokes each owner and does not iterate that inventory. The verifier admits original nested artifacts through their strict existing readers before checking independent expected populations, arithmetic, failure codes, source/corpus bindings and lifecycle relations. Bindings detect accidental substitution within a same-source test, not authenticated producer identity.

## Execution, privacy and failure behavior

Each mode selects source commit/tree/clean status, admitted replay/growth corpus digests and the actual executing build digest independently. Framework runs its DLL through the .NET host; AOT publishes and executes the Linux x64 binary with reflection serialization disabled. A framework report substituted into the native slot fails before normalization. Required focused tests are read from TRX: absent, empty, skipped or failed required methods cannot pass.

The Python supervisor creates a private, unique temporary root outside source. It bounds command time, capture size, trace size and trace count; captures stdout/stderr privately; and prints only fixed stage diagnostics and bounded source/verdict facts. Scenario subprocess environments contain only selected runtime/path/locale/private-home variables. Ordinary C2 cases refuse secret reads; the credential test uses explicit synthetic canaries and a capture-only HTTP handler. Every C2 launch is required to use the loopback transport.

`strace -ff` follows scenario processes and descendants, excluding restore/build/test infrastructure. Any observed AF_INET/AF_INET6 socket construction or connect/send attempt rejects, including loopback in ordinary scenarios. A bounded loopback port-9 probe is the sole deliberate audit positive control and must be detected in both modes. This is observation and fail-closed validation after a syscall, not a production network sandbox or pre-syscall prevention.

After each scenario command, the supervisor checks its process group/private environment namespace for remaining processes and its private tree for retained `apr-*` state roots. A timeout kills only the launched group and fails. Controlled cleanup/unreaped reports remain negative evidence: their fixture verifies the failed attribution and proves workers absent before explicit cleanup. A separate zero-exit retained-root producer must leave exactly its marked probe directory, which the outer supervisor detects before safely removing it. Unexpected state is never removed to manufacture a passing cleanup result. A failed run retains private captures for local diagnosis; CI does not upload or print them. A successful run deletes its entire owned root and confirms absence.

Both actual binaries execute 38 zero-exit hostile-producer/retained-state probes: missing/duplicate/renamed/reordered/substituted cases; wrong source/tree/clean/build/mode/corpus; invalid binding; valid-but-wrong currency artifact; pricing/chain/live/cleanup/worker corruption; unknown/duplicate fields; raw or escaped canary; extra JSON record; stderr leakage; and retained state. Correctly rebound semantic substitutions also cover equal-total aggregate inputs, wrong nested C1 corpus, P1 digest/generation values, P2 session/phase-plan identity, Host pre-reset epoch/session preservation and closed Host status/diagnostic values. The verifier must reject every invalid report, while the outer supervisor owns retained-state rejection. Original positive reports must pass first.

## Cross-mode projection

All original report admission and selected invariants precede projection. T3 pins ordered per-call usage and populations independently of equal totals or rounded amounts; ordinary C1 binds both sides to the selected replay corpus. P1 uses the existing observation value-domain validator. P2 verifies one session across the chain, one domain within each observed phase, distinct predecessor-bound phase plans, and preserved Host epoch/session identity until explicit reset. The projection retains complete case order, selected faults, source/corpus, provider/configuration, tariff policy, scheduled and attempted population, failures, allocations, exact sends/tokens/amounts, acceptance/reset/capacity/restore facts, byte/count measurements, provider segments, control/history segments, prefix stability and quality/control dispositions.

Only explicitly enumerated execution-specific fields are normalized: per-mode build/plan identities, campaign/attempt/startup/process IDs, accepted session/envelope/receipt identities and their validated associations, realized times after ordering/deadline/spacing checks, and hashes transitively containing these generated identities. Restored logical continuation hashes include random session identity; their validated relationships and counts/bytes remain. P1 uses fixed identities and retains all segment hashes. There is no recursive removal of hash-like fields or whole-artifact reduction to a pass flag. Repeated-worker tests exercise permitted volatility; strict readers, case-specific assertions, hostile producers and final byte parity retain stable drift sensitivity.

Passing proves deterministic synthetic behavior on the recorded source and both runtime modes. It does not establish actual provider cache hits/economics, current prices, live quality, independent human confirmation, verified preregistration, formal regression success, promotion approval or R7 readiness. Unknown and inconclusive quality/control states remain visible.
