# Review Deadline

R7-R5 uses a 900-second current Agent review allowance. The authoritative `deadline_seconds` row in `AgentLimits` and `AgentCanonical.LimitsBytes` contains 900; selected-current continuation with a previous limits identity remains incompatible and fails closed. The retained Output8192 and Output65536 evaluator profiles keep their 300-second identities and execution allowance.

The Agent measures one monotonic interval with an injected `TimeProvider`. Request preparation, provider response admission, ordinary tools, recovery and terminal validation consume its remaining time. Trusted Host headroom can shorten that interval without changing the configured canonical identity. Caller cancellation takes precedence over simultaneous expiry. Expiry returns `agent_deadline_exceeded`; it cannot produce an eligible completed session or a normal clean review.

DeepSeek remains non-streaming (`stream: false`). A complete attempt has a 300-second timeout covering send, headers and the entire success or error body read. It is **not first-token latency**. Its effective bound is the intersection of 300 seconds and remaining review time, using the same injected clock. Connection establishment additionally retains its 15-second cap. The actual socket connect operation is linked to the attempt token because cancelling the HTTP request waiter alone can leave connection work running. The sanitized transport outcomes are `provider_timeout` and `connect_timeout`; these become an incomplete provider/Agent failure, while review expiry and caller cancellation retain their distinct Agent reasons. Retries remain disabled in this change. Pre-dispatch cancellation sends nothing; a dispatched timeout retains unknown usage unless validated usage was already captured.

Host composition starts its clock before authorization. All pre-publication phases receive cancellation bounded by 24 minutes from that origin, including policy, snapshot/materialization, state and Agent work; their existing local bounds remain tighter caps. The Agent receives at most the remaining pre-publication time. Ordinary pre-provider classification uses the pre-publication deadline. Selecting an existing post-write acceptance, anchored-write, committed-state or cleanup recovery starts the independent finalization window immediately. Publication/finalization or cancellation after current-run activity starts at most one independent four-minute reconciliation window, capped at 28 minutes from Host entry. It never restarts during recovery. Already-dispatched mutations retain committed/not-committed/unknown semantics; business cancellation cannot discard reconciliation, and hard expiry cannot authorize further I/O or new acceptance. Once acceptance is verified, expiry during optional inline or cleanup work stops that work but preserves the Accepted completion; interrupted inline work retains the existing inline-warning status. State visibility waits and storage/publication readbacks share this independent bound. A hard process kill can still leave an unknown outcome.

Production state restoration receives a latest-acceptance timestamp anchored to the original 28-minute horizon. Locator and lineage provisioning cover that timestamp rather than granting another full allowance when restoration starts. Existing eight-day candidate storage requests exceed the seven-day logical retention plus this Host horizon. Retained direct proof callers keep their previous 900-second allowance, and previous-key retirement evidence freshness is unchanged. The consumer workflow's 30-minute envelope reserves room for wrapper cleanup; this runtime change does not alter workflow authorization.

Sticky and inline transports receive a dedicated Host reconciliation token independently of ordinary caller cancellation. It bounds dispatched mutations, response bodies and post-write readbacks, including individual-comment fallback. GitHub connection establishment is linked to the same request token so a cancelled HTTP waiter cannot leave connection work running. A dispatched write interrupted by the absolute bound remains outcome-unknown; ordinary cancellation alone still permits bounded readback.

Deterministic tests use a timer-capable clock for complete body reads beyond 120 seconds, review/tool work beyond 300 seconds, exact expiry, shorter Host headroom, in-flight state cancellation, late retention coverage, and reconciliation waits crossing the hard deadline. Production Host tests use the real inline hook and HTTP transport to cover batch/individual sends, body reads, readback and ordinary-cancellation completion, then restore accepted state without another provider call. Windows integration covers the framework runtime; Linux Native AOT remains a CI gate.
