# Review Deadline

R7-R5 uses a 900-second current Agent review allowance. The authoritative `deadline_seconds` row in `AgentLimits` and `AgentCanonical.LimitsBytes` contains 900; selected-current continuation with a previous limits identity remains incompatible and fails closed. The retained Output8192 and Output65536 evaluator profiles keep their 300-second identities and execution allowance.

The Agent measures one monotonic interval with an injected `TimeProvider`. Request preparation, provider response admission, ordinary tools, recovery and terminal validation consume its remaining time. Trusted Host headroom can shorten that interval without changing the configured canonical identity. Caller cancellation takes precedence over simultaneous expiry. Expiry returns `agent_deadline_exceeded`; it cannot produce an eligible completed session or a normal clean review.

DeepSeek remains non-streaming (`stream: false`). A complete attempt has a 300-second timeout covering send, headers and the entire success or error body read. It is **not first-token latency**. Its effective bound is the intersection of 300 seconds and remaining review time, using the same injected clock. Connection establishment additionally retains its 15-second cap. The actual socket connect operation is linked to the attempt token because cancelling the HTTP request waiter alone can leave connection work running. The sanitized transport outcomes are `provider_timeout` and `connect_timeout`; these become an incomplete provider/Agent failure, while review expiry and caller cancellation retain their distinct Agent reasons. Current-profile retries follow the bounded policy below; retained profiles remain single-attempt. Pre-dispatch cancellation sends nothing; a dispatched timeout retains unknown usage unless validated usage was already captured.

Host composition starts its clock before authorization. All pre-publication phases receive cancellation bounded by 24 minutes from that origin, including policy, snapshot/materialization, state and Agent work; their existing local bounds remain tighter caps. The Agent receives at most the remaining pre-publication time. Ordinary pre-provider classification uses the pre-publication deadline. Selecting an existing post-write acceptance, anchored-write, committed-state or cleanup recovery starts the independent finalization window immediately. Publication/finalization or cancellation after current-run activity starts at most one independent four-minute reconciliation window, capped at 28 minutes from Host entry. It never restarts during recovery. Already-dispatched mutations retain committed/not-committed/unknown semantics; business cancellation cannot discard reconciliation, and hard expiry cannot authorize further I/O or new acceptance. Once acceptance is verified, expiry during optional inline or cleanup work stops that work but preserves the Accepted completion; interrupted inline work retains the existing inline-warning status. State visibility waits and storage/publication readbacks share this independent bound. A hard process kill can still leave an unknown outcome.

Production state restoration receives a latest-acceptance timestamp anchored to the original 28-minute horizon. Locator and lineage provisioning cover that timestamp rather than granting another full allowance when restoration starts. Existing eight-day candidate storage requests exceed the seven-day logical retention plus this Host horizon. Retained direct proof callers keep their previous 900-second allowance, and previous-key retirement evidence freshness is unchanged. The consumer workflow's 30-minute envelope reserves room for wrapper cleanup; this runtime change does not alter workflow authorization.

Sticky and inline transports receive a dedicated Host reconciliation token independently of ordinary caller cancellation. It bounds dispatched mutations, response bodies and post-write readbacks, including individual-comment fallback. GitHub connection establishment is linked to the same request token so a cancelled HTTP waiter cannot leave connection work running. A dispatched write interrupted by the absolute bound remains outcome-unknown; ordinary cancellation alone still permits bounded readback.

Deterministic tests use a timer-capable clock for complete body reads beyond 120 seconds, review/tool work beyond 300 seconds, exact expiry, shorter Host headroom, in-flight state cancellation, late retention coverage, and reconciliation waits crossing the hard deadline. Production Host tests use the real inline hook and HTTP transport to cover batch/individual sends, body reads, readback and ordinary-cancellation completion, then restore accepted state without another provider call. Windows integration covers the framework runtime; Linux Native AOT remains a CI gate.

## Bounded provider retries

R7-R6 permits two additional physical attempts per logical call and eight dispatched retries per review, only for Current. Eligible failures are HTTP 408, 429, 500, 502, 503 and 504, explicit connect timeout, or proven transient connection failures (reset, aborted, refused, timed out, temporary resolution failure, network/host unreachable). Full-attempt timeout, TLS/protocol errors, arbitrary transport exceptions, authentication/payment/configuration/context errors, malformed responses and tool argument failures are not retry signals. An observed HTTP status remains authoritative if its error body later fails; caller cancellation and full-attempt expiry take precedence. Tools and Host mutations are outside this retry loop. The retained R5/R6 evaluation entrypoint also preserves its existing failure-stopping journal contract, including synthetic plans selecting Current; adopting provider retries in that harness requires separate evaluation authority.

One logical request freezes messages, tools, continuation, thinking and max_tokens. Each physical attempt uses a fresh owned HTTP handler/client under the unchanged endpoint, credentials and security policy, and disposes it before backoff. Each attempt freezes and debits validated usage before retry admission. A retry requires an observed, dispatched and reconciled failed attempt; an uninstrumented transport remains explicitly unavailable and cannot authorize another send. Complete error JSON below the 8192-byte discard cap can provide numeric usage through the same validation as successful responses; malformed, duplicate, truncated or at-cap bodies remain unknown. Error prose never controls eligibility. Unknown usage is potentially billed, not zero; reported sums remain observed lower bounds. This is neither a hard monetary cap nor an exactly-once billing guarantee.

Retries require remaining input/cache/output budgets and output headroom at least the original max_tokens; a smaller remainder stops with TokenLimit rather than resizing the request. Attempt reservations that never dispatch do not consume the eight-send limit. Logical ModelCalls increments once; attempts, retries and failed sends reflect physical dispatch. Only the final admitted response can append history/continuation or execute tools.

Injected full jitter uses additional-attempt ordinals 1 and 2 with windows [0,1s) and [0,2s), with an exponential cap of 30s. A single valid Retry-After delta or HTTP date supplies a minimum delay, so it can exceed the jitter cap. The delta or date is anchored at response-header receipt; body processing consumes that wait using monotonic elapsed time, including when reading the body fails. Multiple, malformed or overflowing values are ignored. The delay must be strictly less than remaining monotonic review time; otherwise the failed call remains ChatFailed. Actual expiry returns DeadlineExceeded, and caller cancellation retains precedence. The original review/Host clock covers attempts and backoff without restarting.

The existing `bash runtime/scripts/verify-agent-loop.sh framework` and `bash runtime/scripts/verify-agent-loop.sh all` gates now include the internal `r7-retry` fixture mode. It exercises real DeepSeek transport, MinimalChatClient and AgentLoop with synthetic HTTP in framework and Linux Native AOT, proving fresh handler disposal, identical requests, truthful failed usage, one terminal append, and exact frozen-output headroom equality versus one token below, unavailable-dispatch retry refusal, and elapsed Retry-After on normal and failed body reads. Existing gate modes and historical identities remain unchanged.
