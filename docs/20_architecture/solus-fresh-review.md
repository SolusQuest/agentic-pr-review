# Internal fresh Solus review

CR1-R5 provides the compiled `Application/Solus/SolusFreshReviewComposition` entry. The ordinary Action uses D4's managed package while retaining the APR-native review engine until R6. There is no public CLI, Action input or environment selector for this entry.

The entry shares `ActionHostComposition` preparation: event authorization, trusted exact-object policy, immutable tree and bounded snapshot, Host deadline and live exclusion authority. Its continuation runs before native selected-current restoration. The default continuation retains existing restoration, publisher and bounded recovery. Fresh execution does not access accepted state, fabricate a native SESSION, or invoke GitHub mutations.

`SolusRuntimeConstruction.CreateForAuthorizedReview` binds the live snapshot, five APR read-only tools, installed DeepSeek adapter, R4 accounting hooks and numeric terminal gate. Correlated R3 terminal acceptance and settled R4 numeric eligibility are both required for accepted product review work. Effective calls, timeout and the three token axes cannot exceed either trusted policy or the fixed CR1 ceiling. Oversized instructions/data are refused visibly; provider output options remain fixed.

The trusted caller may supply bounded repository data, such as a review focus, separately from instructions. Data cannot select Host policy, tools, credentials, limits or effects. Accepted findings remain inspectable by that caller. Raw candidate carriers, reasoning, continuation, original exceptions and context envelopes are excluded from ordinary diagnostics/results.

## Separate observations

| Observation                             | Meaning                                                                                |
| --------------------------------------- | -------------------------------------------------------------------------------------- |
| Preparation failure                     | Host admission failed before managed work                                              |
| Context admission and runtime outcome   | Actual same-call package observations                                                  |
| Terminal acceptance                     | Current evidence and correlated receipt passed APR domain validation                   |
| Product review acceptance               | Domain acceptance and R4 numeric eligibility both passed                               |
| Capture status and checkpoint           | Separate restricted transfer and safe execution correlation                            |
| Publication candidate                   | Existing projection/rendering limits and actual exact-head barrier passed at this call |
| Durable acceptance and effect authority | Always false; no transaction receipt or publisher capability is created                |

The optional `IRestrictedContextSink` is scoped to one invocation. Only it receives the envelope. `NotRequested`, `Unavailable`, `Delivered` and `Failed` retain the actual package meanings. Capture failure cannot rewrite valid completed work. A throwing sink may already have copied bytes; failure promises neither rollback nor absence of retention. Delivery does not establish authenticated persistence or accepted successor state. [S3](solus-state-commit.md) supplies the separate internal encryption, storage and product-state acceptance composition; S4 owns restored execution.

Validated work uses `R4ValidatedPublicationReview.TryCreateProjection` and `R4StickyRenderer`, followed by real `ExactHeadRevalidator` execution. Stale/ineligible/missing heads, transport failure, lost authority or cancellation block a publication candidate. This remains an observation, not permission for a later effect: subsequent publication needs current authority, its state transaction and pre-effect head barriers. Existing native recovery remains selected.

## Proof boundary

The managed executable under `runtime/tests/ActionHostTrustedProofVerifier/SolusFresh` calls the real Host front door and installed provider/parser/runtime/tools over controlled in-memory transport. Its sources are excluded from the native verifier. Compiled fault capabilities test export failure and cancellation after a real confined read; repository/model/environment data cannot select them. No live provider or GitHub calls occur.

The fixture retains the thirteen authored [R5 cases](../../runtime/tests/fixtures/agent/r5/quality/README.md), source bytes, findings and observation oracles. Only the native terminal-function carrier becomes Final content. Scorer negatives retain their independent dispositions; an empty terminal gains no invented universal minimum-tool rule. Fresh observations are compared directly to the oracle, without fabricating SESSION admission or claiming the V1 port.

The credential-free selected-runner command is:

```bash
node runtime/tests/ActionHostFixture/verify-solus-fresh.mjs
```

It requires the existing verified package cache and GitHub-hosted Ubuntu 24.04 x64 qualification. Loaded Solus assemblies are compared with verified archives. Output is restricted to a closed numeric/identity schema, including current usage, tool counts, logical/wire/encoded sizes, retained inventory and reservations. Source inspection, native tests and local emulation are supporting evidence. This internal Host proof does not qualify generated Action distribution, production activation, live model quality or billing; D4/D5/R6/V3 retain those gates.
