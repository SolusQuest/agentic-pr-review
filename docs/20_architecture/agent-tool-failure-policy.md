# Tool failure policy audit

Status: prospective design and implementation inventory for PR #321. Historical executions retain their original outcomes. A denied operation does not, by itself, prove that an Agent task must end or that review quality is poor.

## Decision boundary

The runtime owns capability admission, evidence integrity, state association and finite resource bounds. The model may choose another permitted action after a bounded tool denial. It cannot override admission, manufacture an observation, change snapshot identity or increase a limit. Final review quality remains separate from the number or spelling of intermediate calls.

The distinction follows the evaluation ownership established by [#317](https://github.com/SolusQuest/agentic-pr-review/issues/317), but this document concerns production execution. It does not amend historical evaluation rubrics or waive complete-run evidence.

## Coherent first implementation boundary

The first correction covers all normal preflight denials reachable from canonical registered arguments: missing current path and stale listing cursor. It preserves existing argument recovery and treats a parsed-call lexical contradiction, unknown failure code and preflight exception as terminal. This is a class-wide correction across the five read-only tools, not a fixture-specific path exemption.

Preflight is validation-only. Each prepared call is classified once in the Agent response transaction. Continue past recoverable denials to detect a later fatal result; the first fatal result in provider order wins. A batch with only recoverable denials returns one sanitized error per rejected call and `batch_not_executed` for every valid sibling. No member executes. Existing argument rejection takes precedence and never preflights siblings. Existing resource checks retain their precedence before preflight. A fatal preflight still wins before continuation merge; for recoverable-only batches, stage usage, IDs, continuation, feedback bytes and next-request capacity, then commit once only after cancellation/deadline checks. The ordinary limits are the sole repetition bound. The same path/cursor codes returned after dispatch by `ExecuteAsync` remain execution failures, not eligible preflight recovery.

Execution-content failures and rejected terminal completion are explicitly identified design debt, not justified hard stops. They require different durable facts: an executed read may have prior successful siblings, whereas a preflight-rejected batch executed nothing; a rejected finish is not a completed terminal. Do not mislabel those cases to reuse the preflight representation. Their independent history/observation/closure designs must be reviewed before implementation or any claim that all correctable tool errors recover.

## Diagnostics and verification

Economics receipts and strict public observations carry optional closed tool/category attribution using the existing live rejection projector. Historical reports omit the field and retain their exact verdicts. No path, argument, raw-derived hash or exception is retained. A projection is diagnostic only and cannot override Agent admission, create evidence or assert a hidden root cause.

Preflight recovery tests must cover actual SESSION restore -> denial -> corrected current lookup/read -> grounded finish -> build -> restore -> rebuild; all five tools; multiple denials; valid siblings; fatal/denial order; parser/preflight precedence; one classification per member; no rejected-path I/O; fixed-feedback privacy; usage-once and exact/+1 bounds; cancellation; and unknown/mismatched feedback tampering. Keep full local checks, exact-head CI and the unchanged six-slot paid gate. All four previous failed populations remain immutable.
