## Hosted Service And Privacy Limits

The [H2 record](../10_workflow/cr2-hosted-artifact-evidence.md) binds successful attempt-1 runs [A 40061259888](https://github.com/SolusQuest/agentic-pr-review/actions/runs/40061259888) and [B 40061741768](https://github.com/SolusQuest/agentic-pr-review/actions/runs/40061741768) to the approved H1 source and installed V1 Action. All steps, post actions and fixture-stop steps succeeded. Retention until expiry was not tested because deletion occurred first.

Measured C# pair totals were 15 authenticated REST requests, two anonymous ZIP downloads, 231,755 metadata bytes, 11,776 downloaded bytes, three complete censuses, one APR SDK upload call and one exact DELETE. Operator read-only metadata queries, setup traffic and SDK internal HTTP attempts are outside those counters. The pinned SDK's 678-request / 16-MiB application-body ceilings are source-derived conservative bounds, not measured hosted attempts. H2 uses existing `contents: read` and `actions: write` permission classes; CR2 adds no `id-token: write`.

The actual job-log fixed-canary/credential-pattern scans had zero hits and both check runs had zero annotations. Raw private diagnostics are retained privately. Remote summary Markdown was not retrieved directly: validation of known writers is a source-backed inference from the same admitted receipt JSON, fixed preamble and escaped closed Action completion/failure writers. Neither this inference nor fixed-pattern scanning proves absence of arbitrary secrets. Hosted cancellation, permission denial, rate limiting, ambiguous writes/deletes, conflicting census, capacity exhaustion and canary injection were not executed; deterministic H1/T1/T2/V1 evidence retains its own scope. H2's synthetic context does not establish accepted SESSION/lineage restoration, ordinary release-map resolution or provider/model behavior.

## Supported Use And Remaining Work

The product command is `dotnet AgenticPrReview.Runtime.dll run`, exactly one literal argument and no flags. Actual trusted launch uses the verified runtime through FD3 and the verified tree through FD4, private framed stdin/EOF and one `apr.cli.result.cr2` result. Direct invocation must provide the same admitted Actions facts and upload capability; a DLL pathname alone confers no authority. See the [complete invocation contract](cr2-cli-action-contract.md#cli-invocation-and-private-launch).

Full review/restore/publication remains scoped to trusted GitHub Actions on GitHub-hosted Ubuntu 24.04 x64, Node 24 and trusted compatible .NET 10. Build/restore needs the SDK and private package access; consumers do not. Preparation registers secret-free post cleanup, closes its descriptors and passes only candidate locations/identities. Launch revalidates original archives, complete runtime/tree and installed assets, then holds its claim until actual Host close, descriptor release, bridge drain and SDK process/channel closure. Unknown identity/lifetime preserves resources for runner teardown, rather than authorizing cleanup or presentation.

Existing local source/native/direct-runtime validation remains available via [APR validation](../10_workflow/validation.md) and [native development commands](../10_workflow/native-development-tests.md). Complete local/offline and other-CI workflows are deferred. The managed `cr1-solus-internal4-dev` capacity and Solus context `2/1` remain distinct from larger historical native targets and H2's synthetic context. Selected-current incompatible/corrupt state fails closed; explicit authorized reset is preserved, with no automatic conversion, truncation or fresh fallback.

The [final R7 inventory](../90_roadmap/r7-plan.md#final-cr2-inputs-to-open-contracts) supplies each affected open contract's actual CLI/Action/archive/permission/output inputs. Original `S/W/B/T` release identities, public redistribution approval, actual first candidate/map binding, exact-pair qualification, staging, publication and finite adoption authority remain outstanding in R7. Historical CR1/R4/R7 evidence stays at its tested source. D1 supplies no release version, root alias, permission expansion, credential operation, live-provider campaign or administrative closure.
