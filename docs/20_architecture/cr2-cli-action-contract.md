# CR2 CLI, Action and Upload Contract

This is the selected future execution contract for [C1 #446](https://github.com/SolusQuest/agentic-pr-review/issues/446), under the approved scope in [CR2 #445](https://github.com/SolusQuest/agentic-pr-review/issues/445). The complete target is not yet implemented. C2 implements the explicit `run` command, raw launch and C# input/default ownership in the current ordinary Node Action; its H2 completion and artifact executor remain until P1/T1 replace them. The inspected pre-C2 production baseline is `76e13be7f84d2a20e30188984b3949f10f78172d`: the nested Node Action launches the managed no-argument ActionHost, validates typed inputs and completion in both languages, and serves six artifact operations. Remaining result, transport and composition paths stay current until their replacement owners below cut over together. The ordinary release map remains unbound; this contract creates no supported installation or public adapter ABI.

The accepted target is one C# CLI owning every product decision, behind a thin composite and a real internal Node Action. The first complete review, restore and publication flow requires the existing trusted GitHub Actions workflow on GitHub-hosted `ubuntu-24.04` x64. Direct invocation must supply the same admitted facts and private upload capability; merely running the DLL grants no authority. Existing local validation remains available. Complete local/offline and other-CI execution are deferred.

## CLI Invocation and Private Launch

The consolidated product command is `dotnet AgenticPrReview.Runtime.dll run`, with exactly one literal command and no flags. The trusted launcher actually executes the verified runtime through FD3 and the entry assembly in the verified tree through FD4 under the existing managed loading contract; the pathname example is explanatory. `run` avoids colliding with the retained `review --input <path> --output <path> --trace <path>` validation command. The existing `review-live-agent-r3` validation/proof command also retains its separately bounded authority and semantics. C2 inventories their actual callers rather than retiring validation because of its name.

Empty argv, unknown commands, extra flags, duplicate flags or incomplete validation usage return exit 2 with fixed usage text and no product operation. They do not default to review or fall through to the historical no-argument ActionHost. C2 atomically switches the current ordinary Node Action to `run` and the raw launch, and removes zero-argument ordinary production dispatch. Any specifically named historical fixture entry is isolated from that production route, with its remaining caller/retirement disposition recorded by C2 and verified during A1/V1 integration; it is never a public compatibility alias.

`run` reads exactly one private launch frame from stdin, then requires EOF; stdout contains exactly one final result frame followed by EOF. Each frame is a four-byte unsigned big-endian byte length followed by strict UTF-8 JSON without BOM. Reject zero, oversized, truncated, duplicate-member, unknown-member or trailing frames/bytes. Launch maximum is 159,542 bytes; final result maximum is 16,384 bytes. stderr is an independently bounded 8 KiB fixed diagnostic channel, never raw exceptions or input echo; only explicitly admitted proof receipts use their existing private proof sink. No child stdout/stderr is forwarded verbatim into workflow commands.

The launch object has exactly `protocol`, `build_discriminator`, `inputs`, `facts`, `upload_endpoint`, `cancellation`. `protocol` is the literal `apr.cli.run.cr2`; build identity must equal the acquired payload identity. `cancellation` is `active` or `requested` and cannot clear an observed signal. `upload_endpoint` is the private local Unix socket created and held by this Node invocation, not an input-selected URL. `facts` contains exactly the existing `event_json_path`, `event_json_sha256`, `repository_name`, `repository_id`, `run_id`, `run_attempt`, `workflow_path`, `workflow_ref`, `workflow_sha`, `action_source_sha`, `payload_sha256` fields, retaining their current wire bounds and immutable identity rules from `ActionHostLaunchContract`. The Host reopens/digests the event and verifies workflow/run/PR authority; Node's captured facts do not authorize product work.

`inputs` is an ordered array of objects with exactly string `name` and string `value`. The seven allowed names are `github-token`, `provider-api-key`, `state-key`, `previous-state-key`, `config-path`, `pr-number`, `state-mode`. Capture missing Action inputs as empty strings and do not trim. Direct `run` callers may omit entries. C# rejects unknown and duplicate names before handling emptiness. Empty known values mean omitted; nonempty values, including whitespace, remain byte-exact. Null, nonstring or ill-formed Unicode values are malformed launch input. The CLI alone enforces at most seven entries, 64 UTF-8 bytes per name, 16 KiB aggregate names/values, 4 KiB per secret, 1,024 bytes for config path, canonical positive Int64 PR decimal up to 19 bytes, and `auto`/`reset` state mode. Structural controls are rejected by C#; opaque secrets retain their existing byte rules.

Omitted/empty config selects `.github/agentic-pr-review.json`; omitted/empty state mode selects `auto`; omitted PR is resolved or required by the existing event contract. No credential has an ambient fallback. Existing trusted-route credential requirements, 32-byte base64 key validation, authorized reset/rotation, immutable configuration and deny-before-key/provider/write ordering remain C# decisions. Malformed product values yield a C# `configuration_invalid` result, without Node normalization. Node may reject an over-bound frame before delivery to protect allocation, but must forward bounded invalid product strings to C#.

All four secret values are masked before launch or any diagnostic, including values later rejected. Secrets travel only in the private stdin pipe and typed Host credential holders; never in argv, ordinary environment, step outputs, handoff files, durable state or model-visible objects. The child uses the existing closed environment; Node's Actions runtime token/Results URL remain only in the SDK boundary, while the GitHub token reaches only Host GitHub clients and the provider credential only its narrow provider transport. Clear owned buffers at lifetime end without claiming managed-memory erasure guarantees. Masking is defense in depth, not permission to log private bytes.

## Final Result and Presentation

P1 replaces the mirrored H2 consumer contract with one C#-produced final presentation projection. The result object has exactly `protocol`, `build_discriminator`, `process_exit_code`, `outputs`, `summary`, `annotations`. `protocol` is `apr.cli.result.cr2`; `process_exit_code` is integer 0 or 1 for a completed `run`; `summary` is bounded plain text; `annotations` is an array of at most one object containing exactly `code`, `severity`, `message` strings; severity is the wire discriminator `warning` or `error`. C# retains the existing closed codes/severities and semantic result rules; Node only checks shape, bounded printable text and uses the safe toolkit sink. The total frame cap also bounds every field. Node renders summary as escaped literal text, with no raw HTML, workflow commands or active Markdown supplied by private data.

`outputs` contains exactly the following fourteen keys, each a string or null. C# supplies canonical product tokens and exact decimal strings; null means omit that individual output. C# always supplies non-null status, termination reason and both completeness fields; only numerical facts can be unavailable. Node verifies this key set, scalar types and sink safety, compares protocol/build identity and the declared exit code with the observed child exit code, then forwards non-null values without numeric conversion or semantic reclassification. The outer composite has a different representation boundary: GitHub may materialize an omitted inner output as an empty mapped string. Empty or unset outer numerical outputs mean unavailable, never zero; consumers must inspect step outcome and completeness. No layer supplies a numeric default. A1/V1 test the actual inner-to-outer mappings for every unknown numerical output.

| Output                                      | C# meaning                                  |
| ------------------------------------------- | ------------------------------------------- |
| `status`                                    | Existing final Host status                  |
| `termination-reason`                        | Existing closed review termination reason   |
| `model-calls`                               | Known logical invocation count              |
| `provider-attempts`                         | Known physical sends                        |
| `provider-retries`                          | Known additional sends                      |
| `provider-failed-attempts`                  | Known sends without successful finalization |
| `provider-unknown-usage-attempts`           | Sends with unknown usage                    |
| `provider-unknown-cache-partition-attempts` | Sends with unknown cache partition          |
| `attempt-accounting-completeness`           | Independent attempt completeness            |
| `usage-completeness`                        | Independent usage completeness              |
| `input-tokens`                              | Known input sum                             |
| `input-cache-hit-tokens`                    | Known cache-hit sum                         |
| `input-cache-miss-tokens`                   | Known cache-miss sum                        |
| `output-tokens`                             | Known output sum                            |

C# preserves the complete status, termination, summary, annotation and accounting invariants in [the current interface](./action-interface.md), including exact Int64 decimal values, independent completeness, retry geometry and no cache inference by subtraction. Unknown/overflowed usage is never converted to zero, estimates or complete accounting. Proven pre-provider and recovery-only invocation retains complete zero for this invocation. Later Host failures retain already finalized accounting and Agent termination. The result projection carries no prior-run accounting, SESSION, provider continuation, receipts, secret or private path.

Node waits for child close, bridge drain, original SDK promise settlement and required resource cleanup before admitting a result. No result, malformed/extra frame, wrong protocol/build, spawn failure, signal termination, mismatched exit, late receipt/drain/cleanup failure or unconfirmed lifetime produces product success. Once the internal Node Action has started, ordinary bounded wrapper failures use only the existing fixed projection: `status=failed`, `termination-reason=host_failure`, both completeness outputs `unavailable`, ten numeric outputs omitted, fixed summary/error and failing step. This is a transport failure indication, not a synthesized Host outcome. Unconfirmed managed-child termination fails without presentation and retains its actual-child settlement path; unconfirmed SDK quiescence follows the existing fatal no-presentation policy. Neither permits early resource deletion. Once outputs have begun, a sink failure fails the step and does not overwrite facts with fallback outputs or retry sinks. If preparation fails before Node starts, the composite fails with a bounded fixed preparation diagnostic and unavailable outputs: mapped values may be empty, including status/termination/completeness. No shell fallback invents a Host status or accounting; Node's four-value fallback is unavailable because it never ran. Cancellation/hard kill may also leave a prefix or no outputs. Empty or absent outputs never imply zero or complete accounting. A1/V1 cover preparation failure, Node failure, unknown values, cancellation and partial sinks separately.

## Private Upload Capability

The only final Node storage operation is `upload`. It is a private same-build capability, not a public adapter API. C# owns logical/physical naming, encryption and the S2 envelope, retention policy, REST observations, ZIP/envelope acceptance, object selection and deletion. Node owns confined staging and one official `@actions/artifact` `uploadArtifact` call per admitted request. No URL, repository, credential, generic SDK option, overwrite switch, arbitrary file list or command is accepted from the CLI. Retain the existing `official-output.ts` quarantine around SDK stdout/stderr and workflow commands: SDK diagnostics, exceptions, signed URLs and runtime credentials cannot bypass the safe presentation sink. Restore and verify original stream writers before admitting presentation.

Reuse four-byte big-endian length framing over a Node-owned private Unix socket outside the reviewed workspace (0700 parent, no ambient socket selection). One connection has one request and one reply then closes; both are strict UTF-8 closed JSON, each at most 256 KiB. The request has exactly `protocol`, `build_discriminator`, `correlation_id`, `run_id`, `run_attempt`, `physical_name`, `source_relative_path`, `source_size`, `source_sha256`, `retention_days`, `timeout_ms`. Protocol is `apr.sdk.upload.cr2`; IDs/digests bind this invocation, not a state authority. Correlation is a nonempty bounded 256-byte token used once for the invocation, including after failure. Reject replays and close admission at the 4,096 terminal-ID bound rather than evicting IDs. Exactly one upload may be active.

`source_relative_path` is a bounded 1,024-byte relative path beneath the invocation's held staging directory; no absolute/traversal/control/symlink/hardlink/special-file escape. C# writes one completed immutable carrier. Node reopens descriptor-relative with no-follow semantics, verifies owner/mode, regular single-link identity, size and SHA-256, then copies into its own exclusive immutable operation directory and verifies that copy before SDK use. SDK receives only that copy named `artifact-envelope.json`, operation directory as root, `compressionLevel: 0`, requested `retentionDays`, no overwrite. A post-check pathname replacement cannot redirect the SDK to reviewed or outside bytes. Node closes the source descriptor after the verified private copy is complete; the SDK reads only that copy, which Node retains until the original operation settles. This adds no cross-process source-lease protocol. Private ownership and repeated identity checks retain the existing trusted-runner assumption; they do not physically seal files against a hostile same-UID process.

`source_size`, `retention_days`, `timeout_ms` are canonical decimal strings; size is 1..45,399,694 bytes (the existing S2 staging-carrier cap), retention is 1..90 days and timeout 1..120,000 ms. SHA-256 is lowercase 64 hex. Physical name is exactly `apr-object-` plus 64 lower hex, `-`, and 64 lower hex. These are capability caps; Node does not compute the family from logical state or decide retention sufficiency. C# chooses retention by the existing ceil-to-days rule and later verifies actual expiry against the required minimum; platform retention restrictions can fail rather than silently weakening policy. The held invocation run/build identity must match every request. Preserve the existing SDK-call observation bound of the smaller of 30,000 ms and remaining `timeout_ms`, within the 120,000 ms logical-operation cap. A timed-out observer still tracks the original SDK promise and its operation copy; timeout does not establish quiescence.

The reply has exactly `protocol`, `build_discriminator`, `correlation_id`, `dispatch`, `failure`, `receipt`, with the same protocol literal and matching build/correlation. `dispatch` is `not_dispatched` or `dispatched`; `failure` is `none`, `invalid`, `cancelled`, `conflict`, `io`, `outcome_unknown` or `cleanup`. `receipt` is null or exactly `artifact_id`, `archive_sha256`, `archive_size` as bounded canonical positive decimals/lowercase SHA-256 strings (archive size no greater than 45,413,722). These are SDK-observed upload facts, not accepted store metadata. A normal SDK response with valid receipt uses `dispatched/none`; refusal before any SDK call uses `not_dispatched` and no receipt. Any lost/malformed response, exception or deadline after entering the SDK is conservatively `dispatched/outcome_unknown`, with receipt only if already validly observed. Do not infer no mutation from a rejected/timed-out promise. Proven immutable-name conflict is a transport conflict, never permission to overwrite or retry. Valid combinations are: `not_dispatched` with `invalid`/`cancelled`/`io`/`cleanup` and null receipt; `dispatched/none` with a valid receipt; `dispatched/conflict` with null receipt; or `dispatched/outcome_unknown` with null or an already observed valid receipt. Reject contradictory replies as unknown after possible dispatch. Cleanup failure after SDK entry therefore retains `outcome_unknown`, rather than claiming no mutation.

C# reserves the authenticated REST observation capacity and mutation-rate allowance before dispatch, within its existing request/deadline ledger. The former Node upload reserves three REST observations (metadata, archive, producing attempt); these move with the exact verification, retry/rate-limit and cache invalidation rules into T1. SDK-internal service requests/retries are distinct from documented GitHub REST and remain bounded by the SDK/capability lifetime; APR does not add SDK retries or charge imaginary REST requests for them. Invalidate affected collection observations before possible dispatch, including unknown outcomes. Budget exhaustion before dispatch must issue no SDK call; insufficient observation capacity must not create an unobservable mutation.

After the SDK reply C# gets exact artifact metadata, downloads and verifies archive SHA-256 and bounded ZIP/envelope bytes, verifies producer run/attempt and actual retention, and matches encrypted digest/size/physical name before reporting store success. A receipt or ACK alone is insufficient. SDK success followed by a failed observation is a possible committed mutation; preserve that knowledge for the existing reconciliation path. Lost ACK, cancellation or SDK failure after dispatch never causes a replay, new correlation, overwrite or broad cleanup. An absence read while the original SDK operation remains unsettled cannot prove no mutation: it may still finalize later. Only exact read-only observation under existing recovery rules, with SDK quiescence before relying on absence, may establish the object or its absence; otherwise return the existing ambiguous failure and stop fresh business mutation/publication. This does not prohibit the existing journal-authorized bounded recovery operations described below; it grants no new recovery or replay authority.

## Cancellation, Quiescence and Resource Ownership

Cancellation before spawn prevents a child. For an individual request that C# withdraws before SDK dispatch, Node proves `not_dispatched`; after possible dispatch cancellation is not proof of non-commit. During execution Node forwards SIGTERM once and C# stops fresh review/business work through the existing `ActionHostTransactionJournal`. The Host separately retains its existing `ReconciliationToken` and `allowReconciliation: true` gates: already-authorized acceptance recovery, resumed anchored writes, recovery publication and cleanup may include new SDK uploads or exact REST mutations within that established horizon. In particular cancellation after verified sticky publication must not prevent its required acceptance receipt upload. This preserves R4-D10 and creates no new recovery algorithm, retry or mutation permission.

Node must not seal or abort the whole SDK capability solely because caller cancellation was observed. It remains available to the live Host during the bounded reconciliation grace, with each request still subject to confinement/deadline caps. C# alone distinguishes authorized recovery from fresh business work; no Node product classifier or additional purpose flag is introduced. Preserve the existing 130,000 ms process reconciliation grace, then SIGKILL, then 5,000 ms close-confirmation bound. Host completion/close, exhausted lifecycle horizon or unconfirmed child termination seals all new admission; already dispatched work remains tracked. A valid C# cancellation/ambiguous result is usable only after all lifecycle gates pass.

At terminal Host completion or lifecycle failure (not merely caller cancellation), seal capability admission, stop/drain socket connections (existing 2,000 ms drain bound), and track every original SDK promise and its owned streams/resources. A timeout race, cancellation token, socket close, child exit, promise wrapper settlement or successful `kill` is not quiescence. Retain the existing 30,000 ms official-call quiescence bound; successful original SDK completion/settlement must mean it no longer reads staging or emits writes. If that cannot be established, fail closed with no presentation and preserve the invocation's files, descriptors and leases. No speculative helper process is selected to solve this; T2 must demonstrate the official SDK lifecycle at the actual dependency version or report the unmet contract before cutover.

| Resource                                                     | Owner and release condition                                                                                                                                   |
| ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Preparation downloads, runtime acquisition/probe and scratch | Preparation owner closes its live handles/probes before step return; deletes incomplete private work only after confirmed release                             |
| Prepared tree/runtime candidate                              | Preparation transfers paths plus expected immutable identities only; completed candidates remain read-only until launch revalidation or bounded owner cleanup |
| Launch runtime FD3 and verified tree FD4/lease               | Node launch owner reacquires/validates and retains through confirmed child close; release is not authorized by a signal or timeout                            |
| Upload socket and SDK operation copy                         | Node closes admission/drains; retains the private copy until original SDK quiescence                                                                          |
| Host REST clients, keys and buffers                          | C# disposes after bounded Host settlement; never exports credentials to Node presentation or model                                                            |
| Final invocation scratch                                     | Node deletes descriptor-relative only after child, SDK, streams and required leases are released; validates directory identity before removal                 |

An unconfirmed child/SDK operation keeps the relevant runtime/tree/staging leases, even after the supervising operation reports failure. While the supervisor remains alive, keep an observer for the original operation: later confirmed close/quiescence may trigger ownership-safe cleanup, never late result presentation or resumed publication. Fatal supervisor exit cannot promise a later callback; leave uncertain files for runner teardown and preserve inherited child descriptor authority without deleting its tree. If the job is killed before settlement, cleanup is limited to the runner's job-resource lifetime; do not claim recoverable product state from retained scratch. A subsequent run never trusts or recursively deletes an unexplained prior invocation path.

## Composite Preparation-to-Launch Handoff

The outer entry stays `.github/actions/agentic-pr-review/action.yml`, becomes composite, and invokes a genuinely declared nested Node 24 Action at `.github/actions/agentic-pr-review/internal/action.yml`, using the literal `uses: $/.github/actions/agentic-pr-review/internal`. GitHub's [composite metadata reference](https://docs.github.com/en/actions/reference/workflows-and-actions/metadata-syntax#runsstepsuses) defines `$/` as the composite repository at its running commit, without an `@ref` suffix or workspace checkout. A1/V1 qualify that exact resolution on the selected github.com hosted runner; no `./internal` workspace-relative lookup, mutable cross-repository reference or reviewed checkout may substitute. The Node Action is required to receive Runner-provided artifact runtime credentials through the official Action lifecycle; an ordinary shell invocation of a Node script is insufficient. No credential-export step or OIDC permission is added.

Preparation obtains the exact release-map-authorized original archive, verifies extraction/inventory and acquires the trusted compatible runtime under [the managed distribution contract](./distribution.md). Its output is only candidate locations, archive/tree/runtime digests and source/build identity. No secret, serialized handle, success boolean or previous-step marker is authority. Every output path is untrusted input at the next step.

The Node launch step re-resolves installed Action source and map identity from its trusted location; opens candidate runtime/tree outside the reviewed workspace; repeats no-follow/owner/mode/root, full inventory/digest and runtime/loading-configuration admission; acquires fresh live runtime descriptors and a complete verified-tree lease; and performs the existing closed-environment prerequisite probe before launch. It checks identities again at the actual use boundary. Changed archive/map/tree/runtime, switched path, stale descriptor claim, reviewed-workspace candidate or missing identity fails before provider/key/mutation. Preparation's old descriptors cannot survive as authority across steps.

Preparation owns rollback before handoff. Once launch claims the exact candidates, Node owns their cleanup after confirmed release. A1 supplies an always-run cleanup/post path for preparation-only leftovers and failed handoff, using held ownership/identity records and refusing cleanup while launch/SDK leases are active or uncertain. It may preserve uncertain scratch for job teardown. The cleanup path receives no product secrets and cannot turn preparation success into launch authority. The composite passes all seven raw inputs explicitly to the internal Action, with no YAML defaults or expressions normalizing product values, and maps the fourteen outputs directly from that step. The outer/internal metadata, acquisition source manifest and generated bundle checks move together. In particular `launcher/action-source.ts` currently admits the three-file `action.yml`, `payload-map.json`, `dist/index.js` inventory; A1 replaces that executable closure with the actual composite, internal metadata/bundle and preparation assets.
