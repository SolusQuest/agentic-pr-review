## Replacement paths that must not be conflated

The default command path is `RuntimeApplication -> LiveAgentFreshProcessCommand -> LiveAgentFreshProcessDeterministicProfile`. It remains deterministic and does not activate external provider credentials.

The verifier path is `LiveAgentVerifierProfile -> VerifierTransportFactory -> DeepSeekTransport.CreateHandler/CreateForTesting` over a pinned TLS loopback server. It proves the real Agent request writer, response parser, HTTP transport, tools, continuation, state, and fresh-process behavior without contacting an external endpoint.

The structural production real-provider composition is `R3LiveAgentTransportFactory -> DeepSeekTransport.Create -> DeepSeekChatBackend -> AgentLoop`. The permanent oracle admits that single composition and rejects a second command alias, caller root, real transport factory, or `DeepSeekTransport.Create` call.

Issue #114 adds one verifier-private trusted profile that selects that existing production transport factory without adding another Agent, tool, SESSION, STATE, or continuation composition. Its fixture-owned C# supervisor launches the same prepared artifact for the three quality cases, keeps provider and ephemeral STATE keys in exact child environments, and records only bounded public evidence after cleanup. The old direct compatibility-probe project, script, tests, workflow input, and unprotected generic-secret job are deleted; the protected no-publish workflow is the only real-provider verification route.
