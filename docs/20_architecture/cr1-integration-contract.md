# CR1 integration contract

Status: selected contract for [CR1-R1 #397](https://github.com/SolusQuest/agentic-pr-review/issues/397), based on APR `170a46f7cfe04851310de9cbf11c72f183e32ad3`. This defines integration admission and consuming gates. It does not activate Solus execution, change Current limits or state readers, qualify a package/archive, or authorize provider calls, upstream publication or APR release. The [CR1 direction](../90_roadmap/cr1-cr2-plan.md) owns the product boundary; existing operating contracts and historical M/R evidence retain their original inputs.

The isolated numeric helper beside [AgentLimits](../../runtime/src/AgenticPrReview.Runtime/Agent/AgentLimits.cs) rejects unknown profile IDs, negative inventory/growth, requests above six logical calls, excessive current attempts and cumulative overflow/capacity. Its tests exercise the contract without referencing Solus packages or changing the Current registry. It consumes caller-computed **complete** prospective reservations; it cannot authenticate context, measure serialization, prove runtime acceptance or establish useful review capacity. R2/R5/S4 must wire the applicable pre-work gates and verify the actual installed implementation. A successful helper result alone never permits dispatch.

Unmodified `.1` admits scalar synthetic construction/control probes under these controls. It does **not** admit APR's structured nonterminal tools unchanged. Full APR execution waits for G01/G03 and the actual numeric/serialization/API checks at its consuming leaves. A requested unsupported configuration must receive a visible refusal before affected work, rather than using smaller effective values. In particular, `.1` can shrink a turn's effective response bound to remaining retained capacity; APR must refuse before dispatch when the full selected response/reservations cannot fit. An accounting threshold can be crossed by the final response: R4 must prevent a final overrun becoming an accepted clean review.

Current production remains the [Current count contract](../../runtime/src/AgenticPrReview.Runtime/Agent/Loop/capacity.md) and [tool capacity contract](../../runtime/src/AgenticPrReview.Runtime/Agent/Tools/capacity.md): 64 default/128 maximum logical calls per review, 512 budgeted tools, 16 calls per response, 64 KiB tool results, 8 MiB requests, 2 MiB responses and 16 MiB SESSION plaintext, with independent token axes. These are comparison inputs, not automatic requirements to raise every Solus ceiling. V3 must review explicit admitted product defaults/maxima and rejected configurations using useful workloads before D5/R6 activation. Development controls cannot silently become production limits.

### Inventory and byte arithmetic

With one instruction, one new data item, six accepted model records and six tool results, the fresh provider inventory is at most `1 + 1 + 6 + 6 = 14`. A new review replaces the current instruction and appends one data item plus its new model/tool history: `14 + 1 + 6 + 6 = 27`. At most twelve attempts are retained across these two no-retry reviews. Candidate episodes/submissions, recovery actions and their prospective reservations are **additional** retained records. Real recovery-heavy sequences must be counted separately; the witness does not certify every legal sequence. Renewing current work never renews the cumulative attempts, records, inputs or retained-byte allowance.

Byte admission uses the real serializer. Restored admission charges at least the larger of the reconstructed request payload and `encoded checkpoint + current tool definitions + new instructions + new data`. Response, tool, candidate and recovery reservations must then fit. `.1` candidate/context delivery reserves a prospective receipt, another episode and the worst legal correction **before** the Host callback, even when APR intends `End`. Its correction alone can expand to `16,384 × 6 = 98,304` JSON bytes, plus quotes and metadata. Neither a small intended correction nor the 2 MiB internal codec constant removes that reservation: the effective encoded-context ceiling is bounded by the 196,608-byte retained capacity. R5/S4/V3 must measure it, not infer it from counts, token estimates or unescaped strings.

The helper can, for example, admit a measured 49,152-byte retained inventory plus a 139,264-byte **complete prospective** reservation (`188,416 <= 196,608`), and must reject the one-byte-over cumulative boundary. Those numbers are numeric test inputs, not a claim that a real candidate checkpoint occupies either size. Every prospective size includes definitions, full response and applicable serialized bookkeeping. Capture and subsequent-round admission are independently checked; no omission, truncation, compaction, reset or fresh fallback may make the arithmetic pass.

## Selected execution and terminal carrier

`RuntimeAgentFactory.Create` returns `IAgent`; the implementation also supplies `IContextCandidateAgent`. Ordinary `ExecuteAsync` and `ExecuteWithContextAsync` are suitable for startup/control probes, but ordinary `Completed` is not an APR review. A successful ordinary tool batch asks for another model turn, while only provider `Final` reaches the candidate channel. Exposure hooks contain association/accounting metadata, not the final response payload.

For APR reviews, select `IContextCandidateAgent.ExecuteCandidatesWithContextAsync`, configured exposure hooks, a call-scoped `IRestrictedContextSink` and `CandidateExecutionBounds(1, 0, 0)`:

1. Fresh work uses `ContextExecutionIntent.Fresh` and no supplied context. Restoration for a distinct review uses `NewRunFromContext` from an APR-accepted compatible completed context, an exact source-bound `ContextRoundGrant` and freshly injected `IRuntimeContextAuthority`.
2. Register the five nonterminal functions `list_files`, `list_changed_files`, `read_diff`, `read_file` and `search_text`, bound only to the immutable reviewed snapshot. **The model-facing terminal carrier changes explicitly:** the existing `finish_review` domain object (`summary`, `findings`, nested evidence) is emitted as structured JSON content in provider `Final`, with no calls, and delivered directly in `CandidateSubmission.Payload`. This is not unchanged six-function compatibility. It adds no new function tool and does not wrap nested data inside a scalar tool schema.
3. The APR Host adapter parses with `AgentToolArguments.TryFinishReviewProvider` and applies `TerminalReviewValidator` against the current reviewed identity and admitted current observations. Preserve strict fields, canonical domain identity, duplicate rejection, severities, byte/count limits and grounding. Only then return correlated `Accept/End`; invalid data returns `Reject/End`. The current `finish_review` function-call carrier and mixed final/nonterminal output reject on this selected route. No additional provider turn is needed after terminal acceptance.
4. No terminal candidate repair or accepted continuation is selected. Unknown, missing, duplicate or mismatched feedback cannot authorize replay, publication or accepted state. `Reject/End` is an ended cursor, not APR success. Do not cancel the loop or reinterpret `HostStopped` as successful terminal completion.
5. Context admission, truthful runtime work outcome, terminal/evidence acceptance, restricted capture delivery and durable APR successor acceptance remain separate. A successful callback or capture does not authorize a GitHub effect. Existing stale-head checks and deterministic Host publication remain mandatory.

The public candidate DTO allows 65,536 bytes, but `.1` provider final text is capped at 16,384 bytes. The outer bound does not increase the effective production path. R3 proves this bridge with actual packages; R5 proves fresh work/capture; S4 proves the subsequent review. No upstream generic terminal-tool extension is required by this selected carrier.

### Nonterminal correction remains separate

The [current correction contract](./agent-loop-contract.md#bounded-tool-call-recovery) withholds the whole batch for recoverable arguments, lexical paths, current membership and listing cursors; preserves IDs/name/order/continuation; substitutes sanitized rejected arguments and fixed results; and permits a corrected next turn within existing counts, bytes and deadline. It executes no valid sibling and creates no grounding observation. Unknown tools, malformed/reused IDs, invalid continuation, unsafe access, execution/result failures, cancellation and exhaustion remain terminal.

`.1` provider schema validation can reject before APR preparation; runtime domain rejection closes the batch. Its `IRecoverableFunctionTool` concerns interrupted operations and does not implement the correction above. G03 requires a bounded generic pre-invocation correction mechanism or a demonstrated public-API bridge. Do not silently replace correction with fatal-only policy, weaken validation, replay an entered effect or write a second generic APR loop. Candidate repairs stay at zero; this requirement adds no arbitrary-kill or mid-operation recovery guarantee.

### Minimal upstream specifications

G01 can be reproduced against `.1` with these independent `ToolSchema.Parse` inputs; both throw `ToolContractException(UnsupportedSchema)`:

```json
{
  "type": "object",
  "properties": { "lines": { "type": "array" } },
  "required": ["lines"],
  "additionalProperties": false
}
```

```json
{
  "type": "object",
  "properties": { "line_count": { "type": "integer", "minimum": 1, "maximum": 800 } },
  "required": ["line_count"],
  "additionalProperties": false
}
```

These isolate unsupported semantics, not complete schemas to register. The real [read-file writer](../../runtime/src/AgenticPrReview.Runtime/Agent/Tools/ReadFileTool.cs) additionally emits nested `reviewed_identity`, `lines: [{line,text}]`, nullable returned range/truncation reason and observation metadata. Other [tool writers](../../runtime/src/AgenticPrReview.Runtime/Agent/Tools) supply the exact closed success shapes. `.1` requires a supported result schema as well as input schema, JSON depth at most four and at most 128 total properties; extending only schema parsing leaves provider admission, invocation and restoration broken. Optional-only inputs may explicitly add `required: []` without changing meaning. Stripping ranges or encoding arrays into a string is not equivalent. Integral decimal/exponent spellings admitted by APR's bounded normalization must remain admitted; fractions, overflow and malformed encodings must still reject.

Minimum upstream scope is the bounded object/array/nullability and registered scalar constraints those nonterminal consumers actually require, with explicit schema/payload/depth/property limits and rejection of unsupported semantics. Preserve all-member preflight, exact association, trusted capabilities and equivalent historical-result validation. This does not require general JSON Schema, references, arbitrary recursion or generic validation of APR terminal findings: the latter stays in the selected APR candidate adapter.

For G03, supply two unique known nonterminal calls in one provider response: call A has schema-invalid arguments, or a schema-valid `path: "../x"`, missing current membership or invalid listing cursor; call B is valid. Use a reviewed synthetic snapshot and invocation counters. `.1` rejects A in `ProviderResponse.ValidateFor` before `Prepare`, or closes in `ToolBatchOperation` after domain rejection. Required behavior is zero invocation for **both**, original call IDs/name/order and compatible continuation, sanitized rejected-argument marker and fixed errors (including `batch_not_executed` for B), followed by an explicitly bounded corrected model turn. Retain no raw rejected argument or content-derived hash; mint no evidence; charge applicable attempt/record/tool-feedback/byte inventory once. Do not retry the old tool call or grant new time. Historical reconstruction must retain the same sanitized association. Unknown names/IDs, malformed continuation, unsafe I/O and invalid actual results still stop. Upstream owns a generic Host-selected mechanism, not APR-specific path or error policy.

Capacity constructor reproducers are `new RuntimeOptions(maximumAttempts: 65)`, `maximumRecords: 65`, and `maximumRetainedBytes: 196609`; each throws `ArgumentOutOfRangeException`. They establish `.1` ceilings only. A minimal increase request must instead include a failed useful workload, actual high-water inventories/serialized reservations, selected admitted profile and earliest consumer. Preserving all old APR maxima is not the acceptance criterion.

## Context and product invariants

Authorization precedes authenticated state selection/decryption and provider work. Runtime structural/capacity checks precede the exclusive Host claim; provider import and new work follow it. A consumed claim is not refunded or replayed when later import fails. Saved bytes, semantic capability IDs and descriptor equality supply no current authority or proof of the actual effect target.

S1–S4 must bind exact context bytes to APR scope/lineage, package implementation/format, exact pin, candidate-versus-ordinary mode, tools/profile and actual provider persistence options. DeepSeek persistence includes endpoint/model, `MaximumTokens`, both wire caps and timeout. Fresh credentials and current narrow capabilities are reinjected; changing an option can reject even at the same package version. Selected-current incompatibility fails closed and requires an explicitly authorized reset. This adds no cross-version upgrade promise or unfinished-work recovery path.

Host-owned GitHub/Actions credentials, encryption keys, environment/process/services and publication authority never enter generic Agent context. Repository/tool/model content remains untrusted. Restricted reasoning, continuation, raw candidates and context stay authenticated/encrypted and outside ordinary logs, traces, outputs and publications. Current-snapshot evidence, stale-head barriers, truthful incomplete outcomes and deterministic Host writes remain invariant through cutover.

## Practical acceptance scenarios

R5 starts the representative corpus early; S4 and V3 use it before the complete V1 port. The [authored R5 corpus](../../runtime/tests/fixtures/agent/r5/quality/README.md) supplies `cs-defect`, `cs-safe`, `ts-defect`, `ts-safe` and `repository-rule`, plus explicit negatives. Preserve its expected severities, paths, ranges, required observations and rejected outcomes. Do not regenerate expected findings from the runtime under test. The repository-rule case must read the rule, credential call and actual logging sink; a one-file toy is insufficient.

| Scenario                                       | Required independent oracle and proof                                                                                                                                                                                                                                                                                                                     | Owning consumer |
| ---------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------- |
| Useful fresh defect/safe reviews               | Real APR authorization/policy/snapshot/tools, actual package runtime and provider request/parser over controlled transport. Authored defects must be found at expected grounded locations; safe cases and prohibited locations must not produce findings.                                                                                                 | R5, then V1/V3  |
| Same-head subsequent review in a fresh process | Persist only an accepted encrypted context; restore with new current authority. A prior-only fact absent from fresh public input remains available, but restoration itself never re-executes completed historical tools. New current reads are separately counted.                                                                                        | S3/S4, V1/V3    |
| Verified-ahead subsequent review               | Named synthetic successor fixes an old defect and introduces an independently expected current condition/path change. Historical observation IDs/old lines cannot ground current findings; re-observe current source.                                                                                                                                     | S4, V1/V3       |
| Invalid/injected terminal or evidence          | Forged observation ID, wrong path/range, unreturned/truncated-away line, metadata-only evidence, duplicate/unknown fields, mixed calls/final and repository prompt injection produce no clean accepted review or successor. Preserve authored `wrong-evidence`, `wrong-location`, `safe-invention`, `duplicate-proposal`, missing-tool/observation cases. | R3/R5, V1       |
| Correction and refusal                         | Bad nonterminal member plus valid sibling executes neither; fixed sanitized feedback allows bounded correction. Exact and one-over attempts/records/inputs/bytes, escaped wire, encoded context/reservations, budget and cancellation have visible incomplete/refused outcomes. No silent clamp/drop/compact/truncate/reset.                              | R3/R4/R5/S4/V3  |
| Compatibility/authority failures               | Incompatible pin/options/mode/profile, wrong scope, invalid authenticated context, stale selection and duplicate/competing grant fail closed before affected work. Provider-import failure does not refund a consumed claim.                                                                                                                              | S1–S4           |
| Capture/storage/publication independence       | Valid work retains its truthful outcome if capture is unavailable; capture failure, upload/commit failure or stale head cannot manufacture accepted successor state/publication. No restricted content appears in ordinary sinks.                                                                                                                         | R5/S3/S4, D5    |

Each fresh/restored proof records exact APR source, installed package/lock identity, profile and corpus/scenario identity; current logical calls, attempts/exposure, tools and known/unknown token observations; cumulative retained inventories; actual logical, wire and encoded sizes plus reservations; and separate admission/work/terminal/capture/durable-acceptance outcomes. Measure useful tool/history growth and visible exhaustion. Deterministic scripted must-find success is engineering evidence, not live model quality, billing, release or redistribution proof.

R1 validation covers the numeric helper, boundary/overflow/regression tests, source/reproducer inspection, references and required repository checks. It does not execute the scenarios above. R3–V3 provide their named evidence; D5 executes the actual archive and generated Action on the selected runner, and V4 audits the final source/pin. Required unresolved gaps block those consumers and CR1 acceptance.
