# Solus provider and accounting boundary

CR1-R4 supplies a callable managed-only provider/accounting boundary under the [CR1 integration contract](cr1-integration-contract.md). It does not select a production Host route, replace domain findings validation, change the package pin or qualify useful-review capacity. The native/default route remains selected until its owning cutover gate.

`Execution/Solus/SolusReviewBridge` constructs the actual installed DeepSeek adapter with the fixed official HTTPS endpoint, `deepseek-flash`, thinking enabled/high, 1,024 output tokens, the selected wire caps and 30-second attempt timeout. Its provider wrapper receives only the validated provider credential and numeric facts. Host callbacks and candidate validation are separate capabilities; no ambient environment or credential-bearing Host configuration becomes provider input. An injected terminal handler is trusted executable test capability, not a sandbox or model-selectable transport.

The selected development profile allows six current logical calls, six physical attempts and one attempt per logical call. Solus owns scheduling, retry classification, tools and candidate production. The APR boundary does not add another generic loop. Classified 429/503 failures still have no second send in this profile. Supplemental retry/cap tests do not make a different policy selectable in the production bridge.

## Numeric facts and stopping policy

A complete runtime inventory, known dispatch, completed provider outcome, measured token availability and accounting settlement are separate facts. Current execution and full logical/physical attempt identities are checked before projection. Historical usage and unfinished continued-call lineage cannot be silently charged to the new review. Unknown dispatch remains unknown; it is not confirmed no-send. Only confirmed sends contribute to the existing Action send/retry lower bounds.

The bridge preserves independently reported cache-read and uncached-input counters, known zero, nullable core measurements and checked measured-sum overflow. Reservations, conservative charges and pricing claims never become measurements. APR's uncached-input, cached-input and output stopping axes remain separate from Solus's total-input/output thresholds. Missing complete cache partitions conservatively charge full known input to the uncached stopping balance without inventing a measured miss. Independently known cache-read consumption is also checked against its own axis, including when its peer is missing. Stopping balances saturate at the first overrun; measured sums retain their independent overflow semantics.

The current Action cannot express every richer observation. An unavailable/partial inventory, unsupported continued-call lineage or conflicting identity produces unavailable projection rather than manufactured complete zero. Independent cache counters with unavailable input parents remain measured facts; if their aggregate lower bounds cannot satisfy the current Action subtotal inequalities, projection is explicitly unavailable rather than discarding the known detail. The outcome retains the original numeric current usage. Unknown-first-dispatch followed by a successful retry cannot satisfy the existing retry/failed-send invariant; this projection is refused and remains outside the selected no-retry profile. A future admitted retry profile must requalify it.

The provider's output option stays fixed for compatibility with its persistence witness. If remaining output headroom cannot cover that fixed allowance, the next send is explicitly refused. No option rewrite, silent clamp or output truncation is used. One review deadline, bounded by any smaller Host headroom, covers construction, provider work, backoff, tools and terminal feedback. Settlement grace grants closure time only.

## Terminal and Action contracts

`SolusTerminalAccountingGate` checks associated settled current measurements before delegating candidate data to the separate domain validator. A final overrun or unavailable required core measurement cannot receive positive acceptance. Budget refusal uses correlated `Reject/End`, not successful completion or cancellation masquerading as rejection. Exact-ceiling Final can remain eligible; further nonterminal/tool/provider work cannot be admitted at exhaustion. Runtime completion and numeric eligibility do not authorize publication, successor state or accepted findings.

The Action still exposes fourteen outputs. The additive closed reason `resource_limit` represents runtime exhaustion whose specific dimension is unavailable; the bridge never guesses model/tool/token/context exhaustion from coarse `ResourceLimit`. Existing enum values and reason strings remain, unknown spellings reject, and reviewed statuses reject resource exhaustion. Observed cancellation, deadline and product token refusal retain their own reasons.

The numeric projection freezes once at terminal return. Late provider completion cannot rewrite it. Required bounded settlement still reaches the Host hook; missing, failed, unknown or mismatched feedback never becomes permission. Restricted reasoning, continuation, candidates, raw HTTP bodies and original exceptions remain outside normal diagnostics and Action output. Provider persistence forwarding preserves exact profile/attempt/replay association; its witness is not Host authentication. S1–S4 continue to own encrypted provenance, compatibility and exclusive state authority.

## Verification

The independent `SolusProviderAccountingFixture` exercises the real package writer/parser over controlled in-memory transport, actual runtime and guarded synthetic tools, candidate acceptance/refusal, current/historical usage, numeric boundaries, continuation/persistence, credential canaries and late completion. It emits only fixed failure case IDs or bounded aggregate proof counts; no private package, provider response or context bytes are published.

Its trusted workflow step runs after the existing exact-head cold package/lock/hash proof, using the verified cache without restore credentials. It compares fixture-loaded Solus DLL bytes with their original verified archives before execution. Both the accepted S1 proof step and the R4 step remain in the strict workflow allowlist. Qualification requires the actual final-head Ubuntu 24.04 x64 run and ordinary CI; local macOS results, source inspection, native tests and startup construction alone do not establish this provider proof. Live provider quality, production profile capacity, Host composition and managed artifact loading retain their separate owners.
