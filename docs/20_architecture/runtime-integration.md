# Runtime integration validation

[Managed Solus package construction](../10_workflow/solus-package-consumption.md) has a separate exact-head trusted cold-cache proof. The retained deterministic smoke below does not substitute for that constructor, lock/source or private-producer evidence.

The [CR1 integration contract](./cr1-integration-contract.md) inventories this deterministic protocol smoke separately from actual Solus review qualification. D5 owns the affected managed replacement commands and selected-runner archive/Action proof. The framework/AOT evidence below remains limited to the current implementation; it does not establish Solus execution or managed loading closure.

`npm run runtime:integration` is the repository-owned retained CLI integration entry point. It publishes the framework-dependent C# runtime into a temporary directory outside the repository workspace, runs the deterministic `review` command directly, and verifies schema-valid Input/Result/Trace artifacts without recreating the removed TypeScript launcher.

On Linux the command also publishes the `linux-x64` Native AOT runtime and runs the same direct CLI smoke. On non-Linux it runs the portable framework subset and prints explicit `NON_PORTABLE_CASES_SKIPPED` and `AOT_SKIPPED_NON_LINUX` notices. Linux CI is the release-gating proof for Native AOT. The separate ActionHost framework verifier owns the real W2 wrapper, process lifecycle, cancellation, closed-environment, and privacy proof.

W3 removed the old `src/runtime-integration/runtime-integration.test.ts` harness and its dedicated `runtime/tests/IntegrationFixtures/` executable together with the two TypeScript launcher families. Their process and privacy assertions are now owned by W1/W2/E1 replacement evidence; no compatibility launcher or alternate ActionHost route remains.

R1 retired the checked-in old Action smoke together with the mixed public Action. Retained C# Host tests and E1 framework scenarios verify manifest review-input and target/review binding, sanitized artifact contents, trace and runtime-session non-persistence, failure publication barriers, and the child environment allowlist. R4 distribution tests separately validate the exact nested Action contract, generated-wrapper reproducibility, isolated no-`node_modules` execution, and private prepared-payload mismatch barrier; `runtime:integration` itself claims only the direct retained CLI smoke described above.

The normal state bundle contains host-owned manifest, structured result, and rendered review files. Deterministic runtime input, result, and trace files are not persisted in that bundle.

The managed production no-argument Host enters `SolusManagedActionComposition`. The retained `review-live-agent-r3 --mode bootstrap|continue --root <physical-root>` command enters the same pinned Solus review boundary through a genuine direct filesystem capability. It remains a deterministic verification command: the compiled HTTP handler supplies synthetic responses through the real package serializer/parser, with no live model call. It has no numeric configuration surface and uses the managed defaults. A second independent process must recover the prior-only fact from authenticated Solus context, execute a current snapshot tool and commit a successor using the shared prepare/reconcile/accept transaction. Direct continuation still requires an explicit selected-current locator, VerifiedAhead transition, distinct invocation and the exact prior lineage/version; Action same-head support does not relax this direct contract.

The direct capability retains the real root owner, original authorization file identity and content hash, immutable reviewed inputs and Linux exclusion for the complete operation. It cannot be fabricated from an Action launch DTO, restored bytes or a public digest. Restored direct work obtains the original retained-state token only after an authenticated source claim is durably written and read back. A spent source, incompatible context or genuine old SESSION fails before provider work. The direct contract adds no reset operation or arbitrary-kill recovery guarantee.

`bash runtime/scripts/verify-solus-production-cutover.sh` runs the existing isolated Linux archive qualification with the added direct cases. Both independently built original archives retain their literal entries, dependency closure and all member hashes. Separate supporting executables prepare inputs and produce a genuine historical SESSION; neither replaces an archive entry. The consumer has only the installed .NET runtime, no SDK/package-cache access or external routes. Direct bootstrap/continue, old-SESSION rejection, actual-state versus absent-locator conflict, same-head rejection, repeated invocation and spent-source rejection are observed in fresh processes. The source/head and workflow receipts must be retained alongside the proof; a supporting managed compile is not this qualification.
