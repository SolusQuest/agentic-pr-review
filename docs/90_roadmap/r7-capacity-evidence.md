# R7 capacity evidence

Issue #358 qualifies representative larger deterministic reviews and fresh-process continuation after the R7 capacity owners. Run `bash runtime/scripts/verify-r7-capacity.sh all` on Linux x64 with the repository's pinned .NET SDK and Native AOT prerequisites. The gate builds and executes the evaluation fixture once per framework/AOT mode, validates the authored corpus, runs the focused regression tests, compares semantic receipts and verifies cleanup. Runtime CI invokes that exact command as the final unconditional step of `r5-evaluation-gate`, after preserving its existing R5 proof. All current-head checks, including this job, are required for readiness.

The default workload uses the current unoverridden 64-call/512-tool/900-second authority: 63 turns of seven tools plus one terminal call, charging 442 tools. The configured workload uses supported 128 model calls with other default limits: 127 turns of three tools plus one terminal call, charging 382 tools. The framework gate separately executes the existing production trusted-configuration regression `TrustedConfiguredCallsReachRealProviderAndBothSessionConsumers`, including successful and exhausted 128-call cases. Native AOT executes the selected effective 128-call authority through the real loop, provider backend, SESSION and restricted state consumers.

Both workload snapshots contain 320 changed files, each with a canonical diff of 64 added lines: one short canary line followed by 63 lines of 512 UTF-8 bytes, plus framing. File contents exactly match their diff. Their aggregate exceeds the old 8 MiB snapshot ceiling, while every source stays below the current 2 MiB per-file cap and the aggregate below 32 MiB. The actual production tools paginate all 320 changed files, read a diff and issue first-line file reads. Small per-read observations keep these combined workloads within the provider's conservative context admission. The independent 500-file, 32 MiB aggregate, 2 MiB source, 1 MiB raw read, 800-line read, 4,096-message, 8,192-part and 16 MiB SESSION limits are separate ceilings; this proof does not claim that all maxima can be reached together.

The cross-process topology uses the production `AgentLoop`, DeepSeek request writer/parser, `SnapshotToolExecutor`, stable request materializer, SESSION builder/codec/restorer and `RestrictedStateService` with the encrypted local opaque store. A deterministic accounted transport supplies responses without HTTP. Each child has a new actual process identity and a cleared environment. Bounded private IPC carries only a synthetic key, accepted lineage, plaintext digest and scenario metadata. Every real provider send checks the entire authored history for assistant reasoning, IDs, arguments, tool-result association and untrusted user/tool roles; successful continuations compare the complete restored plaintext digest. Ciphertext and stored names are scanned for repository canaries, and reports contain only fixed identifiers, counts, hashes and measurements. Marked private roots are removed and children reaped on every exit.

After the default accepted predecessor and a successful fresh continuation, five failures exercise real production boundaries. Decoded reasoning exceeds the 1 MiB content cap by one byte; conservative context admission refuses a 1,000,000-byte current user context before dispatch; known synthetic output usage exceeds 524,288 tokens by one; a fake transport refuses a body beyond 2 MiB; injected monotonic time reaches the 900-second deadline after send. Each result must be incomplete, lack a terminal review, reject SESSION construction, leave the complete state inventory unchanged and restore the exact accepted predecessor again. Large-history role and tool-result association mutations are rejected at production SESSION admission. Wrong policy/session scope restore of selected current state must fail without automatic bootstrap or writes. An explicit production reset removes the old authorized scope before a fresh session; its next child restores only fresh history.

The separate Host topology composes the production ActionHost over synthetic GitHub/artifact/publishing ports. It seeds a 64-call accepted review, attempts each of the five real Agent failure stimuli as a continuation, then resets and continues a fresh session. The failed completions must have canonical exit 1, absent finding count/reviewed SHA/publication URL, `NotCommitted`, no sticky or candidate mutation and unchanged accepted state. Capacity/context/output/response failures are `AgentResultInvalid`; deadline failure is `ProviderFailed`. Protected candidate/acceptance/lineage ciphertext remains byte-identical and a store hook rejects protected uploads even if they could later be deleted. The existing Host recovery prelude may clean authenticated publication intent/failure/abandonment/cleanup control objects from a prior completed publication; that cleanup is distinguished from accepted predecessor state. This Host proof is in-process; the large snapshot/local store proof uses fresh processes. These are bounded synthetic integration proofs, not qualification of a released payload, external provider reliability, review quality, billing or paid economics.

Measurements start before snapshot construction and distinguish monotonic wall duration, managed bytes allocated during the scenario, observed working/peak working set, largest project/provider request and response, message/part/SESSION-record counts, plaintext/envelope bytes and aggregate stored bytes. Working sets include runtime/harness overhead and are observations on the executing host; no universal RSS threshold is invented. Framework/AOT semantic parity excludes elapsed time, allocation, process memory and process identity, and randomized encrypted storage size; all diagnostics, workload counts, serialized plaintext/envelope sizes and role/restore/reset observations remain compared. Each child has five minutes of harness supervision and the complete scenario/Host execution has ten minutes; harness timeout is separately classified and cannot be a product capacity success. The context refusal charges one logical model attempt with zero transport dispatches.

The earliest deliberate failures are parser content admission, provider context admission, cumulative output accounting, bounded response transport and the monotonic deadline respectively. Restorable history can therefore fit SESSION/state byte ceilings yet fail the next provider context projection. Per-call response and output allowances also constrain usable growth before nominal message/tool ceilings. Reset is an explicit recovery choice and never converts an incomplete review into successful no-findings output.

The gate's complete case verifier rejects missing/duplicate cases, wrong source/cleanliness, fabricated success or counts, missing associations, preservation/reset failures and false Host completion. Focused tests additionally exercise mutated receipts and a real large accepted history's role/association/policy/scope rejection. The configured-authority regression is required by TRX readback, so an empty test filter cannot silently pass. Old R3/R4/R5/R6 campaigns and runtime proof inventories remain intact.
