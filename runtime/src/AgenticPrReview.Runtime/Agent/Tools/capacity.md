The [review count contract](../Loop/capacity.md) documents charge points and terminal/recovery admission. The [immutable snapshot contract](../../Host/Action/Snapshot/capacity.md) retains its 500-file, 2 MiB per-source and 32 MiB aggregate source bounds, encoding, path and verified-root authority. Truncation is explicit. An omitted line, match, file or hunk cannot ground a finding, and an empty bounded page is not evidence of exhaustive absence. Reviewed code remains untrusted data and is not executed.

A raw 1 MiB file is not promised as a 64 KiB result. A large or heavily escaped first physical line can yield an empty `result_bytes`-truncated read; a later individually fitting line remains reachable. Nonregular files, symlink traversal, NUL/binary data, invalid UTF-8, missing tracked membership and over-bound input retain the existing denial behavior.

Current limits and tool definitions produce new `limits_sha256` and `toolset_sha256` identities. Former identities selected as current fail closed before provider dispatch. This does not rewrite historical artifacts. Restored exact tool results retain their observation IDs and trust classification. SESSION storage, canonical logical history, conservative context estimation and native provider projection have independent bounds; the declared maxima need not fit simultaneously. Native projection reports the established typed `RequestProjection` failure before a physical send when its 8 MiB request limit is exceeded.

## CR1 managed development adapter

The managed-only Solus adapter selects `cr1-solus-internal4-dev` and exact `0.1.0-internal.4` under the [CR1 integration contract](../../../../../docs/20_architecture/cr1-integration-contract.md). The Current limits and six-function production registry above remain active until the owning cutovers. Its five inspection descriptors preserve full nested input/result shapes, APR’s integral provider spelling, immutable snapshot confinement and canonical result/evidence admission. The `finish_review` domain object travels as structured provider Final without function calls, through strict candidate validation and correlated Accept/End or Reject/End.

This development route admits 2,048-byte arguments, 4,096-byte complete success results, at most three calls per batch, six tool admissions/invocations and sequential execution. A legitimate existing writer result above 4,096 bytes fails visibly before Solus success or observation registration; the adapter never clips or rewrites it to fit. Existing explicit page/truncation markers remain data, and only returned lines can ground evidence.

Eligible argument/path/cursor denials select one of 21 static fixed APR feedback variants. A rejected member withholds every sibling before invocation; rejected arguments become `{"_apr_rejected":true}` and otherwise-valid siblings receive `batch_not_executed`. Call IDs, names, order and continuation remain associated. Static selectors are independent of model-visible codes and cannot contain rejected values or their hashes. Unsafe I/O, invalid actual results and invariant failures remain fatal. Generic correction, retained history and count admission belong to Solus; this adapter adds no retry loop.

Each tool set and candidate host is bound to one execution. Restored results remain historical data and never populate its fresh evidence index or replay effects. Same-scope history therefore requires actual current re-observation before a finding can cite it. Candidate acceptance does not publish, persist or claim a successor; those remain separate Host gates. The APR-owned managed fixture exercises actual installed package APIs, schemas/results, target/prepared-handle misuse, exact byte boundaries, correction and restored history, rejected terminal findings and a controlled DeepSeek transport with no outbound request.

## V3 tool and history qualification

The [V3 managed admission contract](../Loop/capacity.md#v3-managed-review-admission) explicitly adopts the existing 2,048-byte arguments, 4,096-byte complete success results, three-member batches and six current tool admissions/invocations. These are default and maximum bounds for this managed route; the larger Current tool limits remain a separate live consumer. A Final candidate is not a function tool and does not consume an extra ordinary tool invocation.

The V3 fixture retains the immutable R5 corpus and uses separately identified authored pressure scenarios. It exercises six tool invocations at the six-call boundary, an accepted three-member batch, a four-member response refusal, an over-remaining whole batch, a seventh required model turn, fixed complete-batch correction, an escaped companion source result and a result above 4,096 bytes. The result failure remains visible, creates no observation for that failed result and cannot yield a clean review or successor. The batch count refusal executes no member. Proposed members, admitted members, actual invocation entries and successful observations are reported independently; correction feedback consumes admissions without being a successful tool observation.

Provider inputs count the currently projected classified history, not the sum of input counts across HTTP sends. HTTP messages and their role counts are separately observed from the actual official provider projection. Complete escaped tool result bytes, logical request/response bytes, individual and aggregate wire bytes and encoded context are separate dimensions. Existing explicit tool pagination/truncation markers remain bounded observation data; they do not permit dropping retained history or grounding evidence in omitted source.

The installed managed gate runs alongside the existing exact result-byte boundary and restored-correction proofs in the same trusted package workflow. The successful useful workload and first visible growth refusal are recorded in the final exact-head receipt. Small constructor tests, old framework/AOT receipts and portable source-only runs cannot replace that evidence or establish a larger product profile.
