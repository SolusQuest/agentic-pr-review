# R7 tool inspection capacity

`AgentLimits` is the numeric authority. `AgentToolRegistry` derives the provider schema and toolset identity; canonical results, SESSION admission and the loop share the same result limits.

| Surface                   | Current bound                                                                                     | Effective behavior                                                                                                                                                                                                                                                                                |
| ------------------------- | ------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `read_file` input         | 1 MiB raw; 800 requested lines                                                                    | Raw UTF-8 bytes include line separators. Returned lines are atomic and canonical JSON can reach its bound before either input limit. `start_line` reaches later individually fitting lines.                                                                                                       |
| Each tool result          | 64 KiB canonical JSON                                                                             | Applies to all five inspection tools after UTF-8 and JSON escaping, including the complete envelope. A valid bounded truncated result can ground only returned evidence.                                                                                                                          |
| Run result accounting     | 8 MiB                                                                                             | Normal results and recovery feedback share checked, transactional accounting. The independent 24-call cap currently bounds ordinary results to at most 1.5 MiB, and a completed run also consumes a terminal call. The 8 MiB cap is not a promise of 128 calls.                                   |
| Search                    | 100 files; 8 MiB total raw; 256 KiB per file; 100 matches                                         | Ordinal literal matching retains its file, raw-byte, match and result-byte truncation precedence. Search has no cursor. Narrow a query for match/output pressure; select an exact path to reach files beyond the scan window. A file may fit `read_file` while exceeding the search per-file cap. |
| Listing and diff pages    | 100 list entries; 20 atomic hunks                                                                 | Canonical bytes can shorten a page. Follow the actual `next_after` or `next_start_hunk`; an oversized first atomic diff hunk returns `tool_result_limit` without an observation.                                                                                                                  |
| Execution and publication | 8 model calls; 24 tool calls; 8 calls per response; concurrency 1; 20 findings; 5 inline comments | Snapshot or inspection capacity does not imply exhaustive review in one run. Batch validation and preflight complete before ordered dispatch.                                                                                                                                                     |

The [immutable snapshot contract](../../Host/Action/Snapshot/capacity.md) retains its 500-file, 2 MiB per-source and 32 MiB aggregate source bounds, encoding, path and verified-root authority. Truncation is explicit. An omitted line, match, file or hunk cannot ground a finding, and an empty bounded page is not evidence of exhaustive absence. Reviewed code remains untrusted data and is not executed.

A raw 1 MiB file is not promised as a 64 KiB result. A large or heavily escaped first physical line can yield an empty `result_bytes`-truncated read; a later individually fitting line remains reachable. Nonregular files, symlink traversal, NUL/binary data, invalid UTF-8, missing tracked membership and over-bound input retain the existing denial behavior.

Current limits and tool definitions produce new `limits_sha256` and `toolset_sha256` identities. Former identities selected as current fail closed before provider dispatch. This does not rewrite historical artifacts. Restored exact tool results retain their observation IDs and trust classification. SESSION storage, canonical logical history, conservative context estimation and native provider projection have independent bounds; the declared maxima need not fit simultaneously. Native projection reports the established typed `RequestProjection` failure before a physical send when its 8 MiB request limit is exceeded.

`R7ToolCapacityTests` reads 800-line pages and searches a real 500-file verified snapshot, checks narrowing and exact-path recovery, raw versus escaped bytes, exact result bytes and returned-only evidence. `ReadDiffTests` preserves count/byte pagination and atomic hunk boundaries. `AgentToolResultBudgetTests` exercises the shared production accounting seam at exactly 64 KiB and 8 MiB, one byte over each, and arithmetic overflow. Loop tests prove ordered successful results above the former 256 KiB run cap. `R7ToolResultSessionTests` round-trips and restores real escaped results above the former limits; provider tests prove accepted projection and earlier typed refusal with zero sends.

`runtime/scripts/verify-agent-loop.sh all` executes the current framework and NativeAOT proof with `runtime/tests/fixtures/agent/r7/tool-capacity/limit-cases.tsv`. Its aggregate-result scenario now completes nine real 30 KiB reads with three model calls, ten tool calls and three synthetic provider requests, without state or lineage mutation. The original `agent-loop/limit-cases.tsv` remains a historical fixture with its original validator and former-limit meaning. Single-result overflow and every other current proof case retain their existing behavior.
