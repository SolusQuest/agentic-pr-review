# R7 immutable snapshot capacity

The Host acquires a frozen base/head pair, reconstructs exact diffs from immutable operands, and admits the resulting snapshot to Agent tools. The three R7-C4 targets are 500 changed files, 2 MiB of canonical diff source per file, and 32 MiB summed across canonical diff sources. A MiB is 1,048,576 bytes. All other limits remain independent admission boundaries.

| Surface                         | Limit                                                                          | Representation and effective boundary                                                                                                                                   |
| ------------------------------- | ------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Changed files                   | 500                                                                            | Host acquisition and Agent admission agree; full 100-item pages require a complete empty terminal probe after page 5.                                                   |
| Changed-file API page           | 100 entries                                                                    | PR and files JSON responses also retain the outer 2 MiB transport cap.                                                                                                  |
| Agent changed metadata          | 256 KiB                                                                        | Sum of canonical changed-file records; 500 maximal-length path pairs are not promised.                                                                                  |
| Exact diff source               | 2 MiB per file                                                                 | Canonical UTF-8 JSON, including identity, hunk coordinates and escaped line text.                                                                                       |
| Exact diff snapshot             | 32 MiB                                                                         | Sum of canonical source bytes; identity framing adds separately bounded metadata to the hash preimage.                                                                  |
| Diff shape                      | 200 hunks per file; 1,000 lines per hunk; 4,096 UTF-8 text bytes per line      | Independent of canonical source bytes; an operand within its raw-byte cap can still exceed these bounds.                                                                |
| Optional endpoint patch         | 512 KiB                                                                        | Supporting endpoint evidence only; omission or incomplete evidence does not replace exact base/head reconstruction.                                                     |
| Tracked paths                   | 20,000                                                                         | Logical leaf paths, including reused objects under distinct prefixes.                                                                                                   |
| Tree metadata                   | 8 MiB                                                                          | Logical complete path bytes and separately bounded Agent tracked-file metadata.                                                                                         |
| Path and depth                  | 1,024 UTF-8 bytes; 64 components                                               | Strict normalized paths; unsupported traversal and link behavior fail closed.                                                                                           |
| Unique head tree/blob objects   | 4,000                                                                          | Independent of logical paths; 20,000 unique blobs are not promised.                                                                                                     |
| Requests                        | 4,096 total                                                                    | Shared across Git objects, archive, PR tuple checks and changed-file pagination. Deep base walks can exhaust this before 500 diffs complete.                            |
| Acquisition and materialization | 300 seconds                                                                    | Shared deadline includes exact diff construction and root materialization.                                                                                              |
| Head blob                       | 8 MiB each; 256 MiB logical aggregate                                          | Reusing a blob does not waive logical bytes at each path.                                                                                                               |
| Base operand                    | 1 MiB each; 64 MiB logical aggregate                                           | Oversized individual base operands produce explicit unavailable diffs; aggregate exhaustion rejects the build.                                                          |
| Materialized root               | 256 MiB                                                                        | Verified regular head content; tree acquisition and root materialization both enforce bounds.                                                                           |
| Git object response             | 16 MiB each; 512 MiB aggregate                                                 | Base/head tree DTOs use the nested Git object transport. Base blobs use raw responses. Base64 expansion, when present in object transport, counts as response bytes.    |

| Decoded archive                 | 342,164,480 bytes                                                              | 256 MiB + 24,000 × 3,072 bytes + 1,024 bytes, allowing bounded tar headers, padding and PAX path overhead. Compressed response bytes still consume the response budget. |
| Stream buffer                   | 64 KiB                                                                         | Bounded streaming avoids allocating a complete untrusted archive or base blob.                                                                                          |
| Tool result                     | 32 KiB each; 256 KiB aggregate per run                                         | Applies after canonical JSON expansion. Atomic hunks cannot be split to fit a page.                                                                                     |
| Tool pages                      | 100 list entries; 20 diff hunks                                                | A byte-limited page can contain fewer entries or hunks and returns an actual continuation cursor.                                                                       |
| File reads                      | 64 KiB raw; 400 lines                                                          | Snapshot capacity does not enlarge read-file output.                                                                                                                    |
| Search                          | 100 files; 8 MiB total raw; 256 KiB per file; 100 matches                      | Independent inspection limits retain their truncation behavior.                                                                                                         |
| Agent execution                 | 8 model calls; 24 tool calls; 8 calls per response; concurrency 1; 300 seconds | Capacity admits a snapshot; it does not guarantee exhaustive inspection in one run.                                                                                     |

`R7SnapshotCapacityTests.FiveHundredFilesAreAcquiredAndInspectedThroughProductionTransports` exercises the HTTP-backed DTO, Git object and codeload archive readers, exact builder, verified materialized root, and actual snapshot tools with synthetic data. Its shallow tree contains 500 unique blobs plus one tree. Acquisition and construction use 514 HTTP requests: 4 head/archive requests, 2 PR tuple reads, 6 changed-file pages, 2 base commit/tree reads and 500 base blob reads. Operands fit the retained individual and aggregate raw-byte caps. The admitted canonical diff sum exceeds the former 8 MiB cap, and one complete source exceeds the former 512 KiB cap. Agent pagination enumerates all 500 records exactly once, then reads a later page of that source and evidence from the last file with the same frozen base/head and source identities.

`ReviewedExactDiffBuilderTests.CanonicalSourceByteBoundariesAreExactAndNeverReturnAPartialSet` separately exercises exactly 2 MiB per source and exactly 32 MiB aggregated over 17 sources, plus one byte beyond each cap. UTF-8 multibyte text, quote, backslash and control-character escaping make raw bytes and canonical bytes distinct. Added-file operands avoid claiming that a 2 MiB base operand fits the retained 1 MiB base cap. Agent admission tests independently exercise the same canonical limits.

An admitted complete source keeps `source_truncated=false`. A paginated tool result can still have `truncated=true` and a continuation cursor. An atomic first hunk that cannot fit a 32 KiB result returns `tool_result_limit`; it is not an exhaustive empty result. Binary, nontext, nonregular and individually over-bound operands retain explicit binary or unavailable classifications. Invalid paths, malformed lifecycle or object identities, aggregate exhaustion and incomplete cap probes return no partial snapshot lease.

The registry change produces a new `limits_sha256` for every limit profile. Current SESSION and stable-plan admission reject the former limits identity before provider dispatch; no conversion, reset or migration is implied. Current proof goldens follow measured new identities, while historical fixtures and validators retain their original bytes and meaning.
