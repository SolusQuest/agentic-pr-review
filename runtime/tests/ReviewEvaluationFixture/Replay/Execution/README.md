# Completed-session replay

Run the test-only executable with `replay --bundle runtime/tests/fixtures/agent/r5/replay`. It needs no GitHub state, provider credentials, or network transport. The checked R2 bundle runs bootstrap, same-head continuation, and an authored verified-ahead transition. Its fact is available through a real seed tool result; the ahead snapshot, diff, policy and fresh context withhold it. The deterministic response derives its continuation summary from the actual restored tool-result slot. This is an engineering continuity assertion, not a model accuracy measurement or permission to ground new findings in old observations.

`ReplayRunner` captures bounded R1 members into an invocation-owned private directory. Each phase re-admits that copy in a fresh executable process. `ReplayChild` uses the real Agent, snapshot tools, DeepSeek request writer/parser and continuation codec, SESSION builder, and encrypted STATE preparation. The child cannot accept state. Only the supervisor calls `AcceptAsync`, after successful child exit, complete source/corpus/phase/session-bound IPC admission, Q1 evaluation, and the scenario assertion. A prepared candidate left by a failed child cannot advance the accepted predecessor. The supervisor checks the predecessor on failure and cleans its private directory after process termination.

The environment starts empty. Only fixed runtime/platform values and private home/temp paths are added. Executable identity comes from the running fixture and installed framework runtime, never from a bundle, shell, caller PATH or caller-selected dotnet host. The child deadline is 45 seconds; supervisor phase waits default to 60 seconds and stream limits are 16 KiB input, 4 MiB total provider request evidence, 8 MiB private reply, and 4 KiB discarded stderr. R1 and production SESSION limits remain unchanged.

Private IPC carries bounded synthetic evidence for independent supervisor checks. Raw requests and SESSION plaintext remain in pipes/memory; only encrypted state is persisted. No child output is forwarded into the public report. The report has separate stable steps and runtime observations. It exposes finite outcome codes, identities, counts, hashes, and explicit cleanup status. Failed phases have no accepted generation or quality score. Cleanup failure makes the invocation unsuccessful.

Normalized comparison includes corpus/case/configuration/snapshot identity, ordered logical records and evidence, continuation values/positions, exact provider request projections, and engineering outcomes. SESSION normalization replaces the generated session ID and predecessor envelope digest, recursively normalizes prior-session identity, and recomputes only the derived stable-plan hashes. It retains all content, call/record order, roles, classification, observation/terminal hashes and continuation bytes. Actual state admission and lineage are checked before this projection; normalized artifacts are never restored or persisted. Actual operation/session/startup IDs, state digests and acceptance timestamps remain separate observations. Compare `normalized_sha256` and `steps`, not raw Q1 execution or encrypted-state hashes, between invocations.

The ordered executor is separate from `ReplayCoverage`, which owns R2's independently compiled inventory/fact/continuation oracle. Later scenario owners can provide their own bounded verification callback and authored R1 history through `ReplayOptions`; they reuse process supervision and state transitions. Authored transition descriptors are test-only authority and never production GitHub ancestry receipts. Public bundles cannot supply SESSION, lineage, keys or executables. Fault controls are internal test inputs used to exercise actual rejection and process boundaries.

Focused tests are `R5CompletedReplayTests`. Full Runtime tests, the retained deterministic R3 verifier, `npm run check`, and distribution checks remain applicable. Linux x64 Native AOT validation must execute replay and its children; publishing a binary alone does not prove this capability. Full R5 CI integration remains a later issue.
