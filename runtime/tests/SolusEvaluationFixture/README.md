# Managed Solus evaluation fixture

This test-only consumer runs actual APR fresh/state-commit/restored compositions and the selected installed Solus packages with authored provider output, synthetic GitHub authorization/repository ports and the encrypted official artifact bridge. The existing `EvaluationScorer`, contracts and JSON reader are source-linked; a fixture-local partial factory admits actual correlated work without a fabricated SESSION.

Run `bash runtime/scripts/verify-r5-evaluation.sh managed` through the existing trusted Ubuntu 24.04 x64 package-proof workflow. `verify.mjs` requires clean exact source and verified installed package bytes. It supplies no source-reference, arbitrary report import, live-provider or qualification-skip switch. Local source-reference compilation is supporting evidence only.

Every independent Host process gets a fresh official bridge server and correlation registry. The same extracted synthetic executor retains encrypted objects and exact metadata across those invocations. The controller closes only an idle previous server and confirms the next boundary before the Host starts; replay protection and the 4096 terminal-correlation limit remain unchanged within each invocation. The existing S3/S4 server CLI retains its original behavior. Verified-ahead readback uses separately authorized current-head facts.

`SolusWitness` excludes historical results and correction feedback, associates actual current model attempts/tool results, and revalidates canonical evidence against APR's admitted current observations. It deduplicates repeated projections by call identity while permitting identical observation hashes from distinct real reads. `SolusEvaluationSubject` checks complete correlated work, canonical Final and current evidence before the shared scorer can evaluate it. Work, publication, capture, durable acceptance and recovery without work stay separate.

The fixed thirteen-case corpus preserves must-find/must-not-find and negative evidence/scenario codes. Additional controls cover source/input/policy leakage, repeated identical reads, authenticated same-head/verified-ahead reviews, tamper/config/import/ancestry rejection, malformed or incomplete work, cancellation, stale evidence/head, and capture failure. A bounded growth sequence reports actual current/history inventories and distinguishes observed refusal from an injected bound. Restricted context is measured only at trusted capture/readback seams and is never used as evaluator or replay authority.

`report.mjs` is an independent outside-in verifier. Its data-admission tests cannot create an actual subject or qualify packages. `native-assertions.json` gives explicit replacement/historical dispositions for 152 old attributed test methods; `assertion-dispositions.mjs` prevents an unclassified inventory change. V1 deletes no native path. The [evaluation contract](../../../docs/20_architecture/r5-evaluation-contract.md), [replay contract](../../../docs/20_architecture/r5-replay-fixtures.md), and [validation guide](../../../docs/10_workflow/r5-evaluation-validation.md) own the detailed boundaries.

All provider output is scripted engineering evidence. The proof reports live calls as zero and live model quality as not evaluated. Synthetic Host publication writes are counted separately; ordinary receipts exclude source, candidates, policy, tool data, reasoning and credentials.
